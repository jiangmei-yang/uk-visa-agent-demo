# 顾问式 Gmail 回复验收（2026-09-05）

## 结论

原顾问文案验收通过了本次**有边界的离线功能验收**：14 个 pytest 用例、10 组场景、21 次自动 Gmail 回复全部到达捕获式 `SENT` 运输，没有真实发邮件，也没有调用付费模型。后续新增的官方流程指引另由聚焦单元/边界回归验收。

这不等于“已经证明像真人顾问一样自然”。自然度没有统一的客观真值；本次只验证了可观测的反机器人指标，并对实际捕获文本做了非盲审阅。因此准确表述是：

- 工作流的相关性、信息量、行动性、连续性和安全底线，在这些受控场景中通过；
- 人工顾问感已明显好于旧版“收到，我再了解一下”式问卷，但长回复仍有模块拼接感；
- DeepSeek 对未见表述的意图识别、真实邮箱的运输可用性、WhatsApp 和真实客户盲测不在本次结论内。

对客户只呈现一个连续的签证材料顾问身份，不让多个“Agent”轮流向客户说话。内部则明确分权：
模型只能提议结构化事实和受限问题主题，官方指引由 reviewed compiler 选择，档案状态由
工作流管理，最终材料包只能由确定性交付门禁释放。这是“一条外部顾问人格，多个内部受控角色”，
而不是让模型自由决定要求、路线或交付。

## 验收方法

回归文件：

`tests/integration/test_consultant_acceptance_2026_09_05.py`

每次对话都经过以下真实代码路径：

1. 固定的结构化提取提案进入 `GuardedLLM`；
2. `WorkflowService` 应用事实所有权、路线、时效和交付门禁；
3. 每一轮关闭再重开 SQLite，避免只在内存中“看起来记住了”；
4. `AutomaticGmailReplySender` 生成 reviewed 回复；
5. `OutboxDispatcher` 真实领取 outbox，发给捕获式 Gmail adapter，并持久化 `SENT`。

测试明确禁用 socket 网络、真实 Gmail 和模型调用。这是为了单独检验“结构化事实已经给定时，顾问工作流能否稳定交付”，不把模型分类准确度混入文案验收。

## 多维度门槛

| 维度 | 本次的可执行判定 |
| --- | --- |
| 相关性 | 同一封邮件的明确问题都有对应内容；不插入已经回答过的无关问卷 |
| 签证信息量 | 不只说“需要材料”，而是说明材料用途、条件和第一个动作 |
| 官方来源 | 只显示 GOV.UK / UKVI 官方 URL；同封邮件不重复相同 URL；超过复核日期时停止展示数字和链接 |
| 可行动性 | 给出可当天执行的动作，如索取什么信、信中核对什么、文件怎样扫描 |
| 连续性 | 日期延后不再追问；更正覆盖旧资金安排；未回答的姓名只保留一个待办，不每封重问 |
| 问题密度 | 实际渲染的主问题每封最多 1 个；到达/离开日期、资助人关系/姓名合并为同一话题 |
| 可观测自然度 | 不出现旧版问卷式开场、内部字段名、LLM/工作流技术语或无意义收条 |
| 安全 | 不预测获批，不发明固定存款门槛，不把未确定行程写成已预订；严重历史立即停止自动评估并转人工 |

官方链接不会在每封邮件里完整重复。只有当前问题或下一个可执行动作需要时才显示，并用“申请与生物信息步骤”、
“递交后与决定通知”等描述性标签说明去向。用户明确说“不要链接”时，保留实质回答、去掉 URL；指引超过复核窗口时，
不继续展示旧金额、旧时间或旧链接。

## 场景结果

下表合并展示原 capture-transport 顾问文案场景，以及 2026-09-05 新增的确定性官方指引聚焦回归；它们共享内容边界，但不应将单元测试解读成 Gmail 投递证据。

| 场景 | 结果 | 主要证据 | 人工阅读备注 |
| --- | --- | --- | --- |
| 模糊首问“需要什么” | 通过 | 先给 6 类有条件的常见材料、3 个官方入口，再只问访问目的 | 信息量足，但首封仍偏“顾问手册”而非短邮件 |
| 同一轮已知护照/目的/地点/身份/资金 | 通过 | 捕获回复复述真正已知事实，不再说“还不知道”；给出个人化待补材料 | 消除了直接伤害信任的自相矛盾 |
| 一封问流程+材料+费用+时间 | 功能通过；文案部分通过 | 同时包含 Apply now、在线申请/预约、条件式材料、£135、通常 3 周和非保证说明 | 所有 obligation 都保留，但整封较长，段落之间仍可以更像顾问一次性整理后的口吻 |
| Standard Visitor 一般资格 | 通过 | 说明允许的访问目的、访问后离境、可承担在英和返程费用、不以频繁/连续访问把英国作为主要住所 | 只给一般框架；不作个人资格结论，不预测获批 |
| 生物信息 / VAC | 通过 | 在线申请后按流程预约，使用护照/旅行证件核验身份，提供指纹、照片及申请页要求的材料 | 具体地点、时段和带什么以实时申请/VAC 通知为准；不再宣称“地点一定不能更改” |
| 递交后进度和通知 | 通过 | 说明起算条件、通常约 3 周、Home Office 通过邮件或信件通知决定，并提醒检查垃圾邮件 | 在官方公布时间内通常无需联系 UKVI 追问；不承诺截止日或获签 |
| 递交后更正 / 撤回 | 通过 | 更正走 UKVI 联系入口；等待决定时可申请撤回，退费取决于当时处理阶段 | 不说“发一封说明就自动改表”或“撤回就一定退费”；UKVI 收到撤回后不能再叫停 |
| 明确要 Student visa 官方申请页 | 通过 | 返回 Student visa 官方页与路线查询页 | 不套用 Standard Visitor 费用/时间/材料，也不因一个问题改写当前档案路线 |
| 自雇：个人与公司账户 | 通过 | 个人账户说明本人可动用的旅行资金；公司/经营记录可说明收入来源与对应转账 | 不把公司余额自动当成个人可用资金，也不发明统一的流水月数 |
| 指引过期 | 通过 | 复核日期后不显示£135、3 周、材料类别或过期链接 | 保守但正确；需配套运营上的定期刷新 |
| 三次说日期未定 | 通过 | 两个日期字段持续保留 deferred，三封均不再问到达/离开日期 | 第三封是简短收条，功能正确，但还有轻微模板感 |
| 自费更正为父亲资助 | 通过 | 档案变为 `personal_sponsor/father`，回复明确承认更正并切换到资助信、费用和支付方式 | 是目前最自然的连续性场景之一 |
| 父亲资助 | 通过 | 回答资助说明 5 项内容、资金、关系、英国身份和第一步；不发明固定余额/流水月数 | 可作为顾问式回复的内部基准 |
| 商务访问 | 通过 | 雇主抬头说明、单位关系、目的、具体费用、支付/报销和可核实联系人 | 不误套个人资助的亲属材料 |
| 会议+单位支付 | 通过 | 把主办方邀请函和单位资助/报销说明作为一组优先行动，分开说明二者证明什么 | 修正了只推在读/在职证明的错误优先级 |
| 拒签/遣返或逖期/刑事定罪 | 通过 | 三类情况全部进入 `HUMAN_REVIEW_REQUIRED`；说明提交完整文件，按国家、类别、日期、原因、后续结果整理时间线 | 既不预测结果，也不再只说“转人工”而不给下一步 |
| 重复问“下一步” | 通过 | 先给预计行程、再给合法居留；姓名问题发送后不再问，改给护照扫描和居留文件任务 | “不重复提问”的解释略显系统化，但实际每次都有新动作 |

## 来源和时效

本次交付的官方页面于 **2026-09-05** 重新核对。当前回复只使用以下官方域名：

- `www.gov.uk`
- `visas-immigration.service.gov.uk`

本次主要覆盖：

- 签证/ETA 路线查询；
- Standard Visitor 一般要求、申请入口与生物信息/VAC 步骤；
- 境外处理时间、递交后决定通知、联系 UKVI 以及撤回申请；
- 访客签证证明材料指南及 sponsor/conference 锚点；
- 明确的 Student visa 官方起点，但不将 Student 规则混入 Standard Visitor 回答。

核对页面：

- [Standard Visitor 概览与一般要求](https://www.gov.uk/standard-visitor)
- [Standard Visitor 申请、身份核验和生物信息步骤](https://www.gov.uk/standard-visitor/apply-standard-visitor-visa)
- [查询签证申请中心](https://www.gov.uk/find-a-visa-application-centre)
- [境外申请处理时间](https://www.gov.uk/guidance/visa-processing-times-applications-outside-the-uk)
- [递交申请后与决定通知](https://www.gov.uk/apply-to-come-to-the-uk/applying-online-and-getting-a-decision)
- [联系 UKVI](https://www.gov.uk/contact-ukvi-inside-outside-uk) 与 [撤回签证申请](https://www.gov.uk/cancel-visa)
- [访客签证证明材料指南](https://www.gov.uk/government/publications/visitor-visa-guide-to-supporting-documents/guide-to-supporting-documents-visiting-the-uk)
- [英国签证路线查询](https://www.gov.uk/check-uk-visa) 与 [Student visa 官方起点](https://www.gov.uk/student-visa)

三个数字必须带着适用边界理解：

- **£135**：2026-09-05 核对的 6 个月 Standard Visitor 申请费；不包括长期签证、其他路线、VAC 增值或加急服务，付款前仍以官网实时页面为准。
- **最早提前 3 个月**：Standard Visitor 可在出发前最早 3 个月申请；不等于顾问确认“时间一定够”。
- **通常约 3 周**：指境外 Standard Visitor 在完成在线申请、身份核验和材料提供后的通常决定时间；不是从开始准备材料起算，不是截止日、获签承诺或护照返还日预测。

`guidance_freshness.py` 的复核日期是 2026-10-04，而当前 policy YAML 的 `valid_until` 是 2026-10-02。本次日期 2026-09-05 同时落在两个窗口内；运营上应以较早的 **2026-10-02** 作为强制刷新截止日，不应等到 10 月 4 日。长期建议将这两个日期合并到一个可审计的来源注册表。

## 现在仍不能宣称的事

- 自然度没有在开放场景中得到证明，不能把这组内部用例外推为普遍表现；
- 不能用这组固定提取证明 DeepSeek 对任意自然语言的识别率；
- 不能由捕获式 adapter 推断 Gmail OAuth、轮询、限流或真实投递永远可用；
- 本次“顾问回复”验收不用来证明文件 OCR、跨文件冲突、最终 ZIP 或外部 transport；这些必须分别引用其他交付证据；
- 本次没有进行外部独立用户验证；不能用自审代替盲测，因此这里只记录内部可重复的功能证据。

## Gmail 与 WhatsApp 边界

- **Gmail 是当前主测试通道。** 仓库另有真实 sandbox 中 OAuth、线程回复、附件和虚构材料包发送的有边界证据；本文的 21 封则是 capture adapter，不能用来重复宣称真实投递、公开收件或无人值守生产。
- **WhatsApp 只复用通道边界。** Twilio adapter 与 Gmail 共用 typed event、档案记忆、reviewed 回答和交付门禁；当前证据是本地 webhook/queue/sender 合约，不是真实手机收发。最终 ZIP 仍经 Email 或 review console 交付，不在 WhatsApp 直接发送。
