# Gmail 使用方式：直接咨询

`service_request` 模式直接处理客户主动发来的咨询和材料，不要求先复制同意句子、
回复参考码，也不发送独立的授权邮件。首次业务回复末尾附简短的资料使用说明。
客户可以要求停止处理。材料确认、客户档案隔离、人工审核和最终发送检查不变。

这是运营者选择的服务交互模式，不是客户同意的证据，也不是法律合规结论。
真实部署前，运营者仍须确定适用的资料处理依据、告知方式和供应商安排。
程序不会伪造同意记录，停止处理也不会自动删除已有资料或撤回供应商已收到的内容。

使用现有 Gmail 配置，以新的状态目录和启用时间启动：

```sh
.venv/bin/python scripts/gmail_sandbox.py serve \
  --sender customer@example.com --mailbox service@example.com \
  --after ACTIVATION_UNIX_TIMESTAMP --state-dir data/new-service \
  --processing-interaction service_request --watch --interval 30
```

替换两个邮箱和启用时间；不要将同一客户交给两个重叠的收件进程。
旧状态目录中已发送的“同意后开始”承诺不能通过切换模式绕过。
请使用新线程验证新交互，不要通过回扫旧邮件补造授权。
默认 `explicit_consent` 为旧部署保留原有行为；新模式必须在启动时明确选择。
