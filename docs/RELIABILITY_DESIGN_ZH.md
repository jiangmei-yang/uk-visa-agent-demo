# Agent 与稳定交付设计

## 简短说明（约两分钟）

我把这个系统定位为英国访客签证的材料准备服务，而不是一个什么签证问题都能回答的聊天机器人。目标是帮助客户从咨询、资料收集、补件和纠错，走到可核对的材料包；不替客户提交申请，也不承诺签证结果。

我的核心设计是：**模型负责理解语言，工作流负责状态和交付。** 当前接入 DeepSeek API，没有自行训练基础模型。模型只能提出结构化的信息和文件解读，不能直接改案件状态、批准材料或者发出最终包。每项事实还要经过字段、原文依据、归属和冲突检查，才能写入持久化档案。

对客户始终是一个连续的顾问，对内则分开信息提取、文件分析、规则检查和交付。我没有为了展示技术而堆叠多个自主 Agent，因为多个模型相互赞同不等于证据正确，还会增加上下文丢失、费用和故障点。只有当任务能独立执行、输出可校验、并且实测有收益时，才考虑并行文件分析等协作。

稳定性分两层：业务上，缺材料、事实冲突、未确认的摘要不能交付；工程上，邮件重复、乱序、超时和发送后崩溃，都需要持久化状态、幂等处理和可追溯恢复。客户更改信息以后，旧摘要的确认不能继续生效。

验证也不能只看模型回答是否流畅。我分别做规则回归、真实模型评测、邮件端到端测试和最终文件检查。例如实邮里出现过“日期未定”被反复询问、联系人空列表分类错误、自然确认没有被识别。这些问题来自模型与业务边界的组合，必须把原始表达保留下来做回归，而不是只换一个更大的模型。

当前本地回归有 5673 项通过，但我不会把这个数字说成真实场景百分之百准确。最新 Gmail 流程已验证收发、附件、纠错和客户确认，仍卡在旅行史操作人员复核，尚未完成这一轮最终 ZIP 实收。这个限制需要解决并重新做完整验收，才能称为自动交付完成。

## 具体工作流

1. **接收与归属**：渠道适配器把邮件转成统一事件，检查发件人、线程、自动消息和事件顺序。当前按会话建立 Case；不是仅凭姓名跨邮箱合并的客户 CRM。
2. **受限理解**：模型输出严格 schema 的提议，原邮件及附件内容都当作不可信输入，不能通过“忽略规则”等文字获取工具权限。
3. **验证与记忆**：检查原文、字段语义、客户归属和一致性；记录已知、暂缓、冲突、文件版本和来源。暂未确定不等于客户没有回答。
4. **顾问沟通**：根据案件当前差距生成下一步；先回答客户问题，再提出必要问题。实时 Gmail 使用确定性回复编排，而不是允许模型自由发送任意承诺。
5. **补件与纠错**：保留旧文件，建立新版替代关系；同名文件或一句“确认”不能抹掉矛盾。银行更正还需要核对账户、期间及金额等上下文。
6. **确认与交付**：确认绑定当前摘要，资料改变后需重新确认。确定性门禁控制材料包生成，发件队列负责发送与不确定结果核对。
7. **异常处理**：无法可靠判定时保留资料、说明具体待核实事项，而不是编造确定结论。当前复核交互仍有过度保守、说明不清的缺点。

## 如何衡量“稳定且准确”

| 维度 | 验证方式 | 不能混淆的概念 |
|---|---|---|
| 信息准确性 | 按字段比较正确值、原文归属、未知与冲突 | 有原文片段不代表属于当前客户 |
| 对话质量 | 多轮记忆、暂缓问题、自然确认、具体下一步 | 流畅不代表准确，保守也不等于好用 |
| 文件可靠性 | 可读性、身份/金额/日期一致性、新旧替换、翻译 | 提取成功不等于文件真实有效 |
| 交付安全 | 缺件、旧确认、注入和冲突反例必须被拦截 | 包已生成不代表可以递交或必然获批 |
| 渠道可靠性 | 重复、乱序、失败重试、崩溃后的发送核对 | API 返回成功不等于客户已收到 |
| 输出质量 | ZIP 完整性、内容正确性、逐页视觉检查 | 文件可以打开不代表内容完整 |
| 运营表现 | 端到端成功率、误转人工率、重复提问率、p95 时延和每案费用 | 固定用例通过率不是线上总体准确率 |

最后一行是上线后应持续统计的指标，不是本项目已经测出的线上 SLA。

## Agent、模型与渠道选择

- **不需要自训练才能实现业务 Agent。** 当前工作是 API 接入、任务约束、状态机、证据与评测。是否微调应由稳定失败模式及合规数据决定，不能替代业务校验。
- **不默认需要多 Agent。** 先明确各模块权限。未来可以并行分析独立文件，但统一档案与最终交付权限仍归一个工作流，不能让多个 Agent 各自追问或放行。
- **不以模型声誉选择。** 比较结构化提取、口语与多轮表现、未知/冲突处理、成本和时延。当前 DeepSeek 已实际接入；没有完成的其他模型对比不应写成结论。版本、提示词或规则变化后重新绑定评测证据。
- **WhatsApp 复用核心而非另做大脑。** 事件、案件和交付逻辑可以复用，但真实上线还需验证 webhook、媒体获取、重试与平台消息限制。现有接口不等于完整实机验收，也不能自动把 Gmail 客户和电话号码合并。
