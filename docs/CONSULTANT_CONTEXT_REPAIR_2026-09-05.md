# 顾问式回复：先解决眼前的问题，2026-09-05

这是一次有界的内容选择和上下文修复，不是“自然度满分”的验收。
用户指出的是信息量和相关性，不只是措辞。默认 Gmail `reviewed` 发送路径会
根据档案重新编排审核过的正文；DeepSeek 的抽取能力不能等同于最终模板的质量。
本轮没有切换线上自由生成、调用付费模型或发送测试邮件。

## 独立复现与修复

1. 连续来信依次说明旅游、中国护照、香港递交，旧回复仍说“具体要准备哪些材料，
   要先看你的出行目的和申请地点”。现在明确承接已经记下的国籍、地点、姓名；
   不再重新欢迎客户或把已知信息描述为未知。
2. 新的申请地点使现有合法居留证明规则适用时，现在说明先找哪些现有身份文件、
   核对什么、为何相关。只提供有界准备建议，不推断申请人已具备居留或签证资格，
   不擅自指定其持有的证件，不将建议计为已提供证据。已经 SENT 的建议不重复，
   当前独立 FAQ 优先，不附带无关教程。
3. “这次不用给我链接”原来会删掉全部主动指导，留下姓名问题。现在只去掉链接，
   保留贴合学生、在职、资助或探亲情况的准备动作和用途说明，也不留下“见下面链接”
   这种悬空指代。真正拒绝材料建议、暂停、过期来源仍保持原有边界。
4. 明确问下一份材料，与问下一个个人信息字段分开处理；选择由现有材料状态和
   规则支持的一项，而不是让缺少生日抢占回复。人工核对、暂停、确认和实际文件
   问题仍优先。一般的“下一步是什么”没有因此获得新的资料处理或交付权限。

## 证据性质

使用虚构文本、人工指定且带原文依据的抽取提案，以及实际 WorkflowService、
GuardedLLM、SQLite、AutomaticGmailReplySender 和捕获式 Gmail 传输。
多轮间重开数据库，检查真实 outbox 的 SENT 正文，而非仅检查文案函数。
这能证明给定合法提案后的行为，不能证明模型在新问题上的分类准确率，
也不是实际收件人的体验试验。

连续对话最初 **8 失败 / 2 通过**；后续增加未知背景、FAQ 优先反例。
链接格式的原单元测试中，两条“拒绝链接必须删除所有建议”的旧断言被拆开：
真正拒绝建议仍要求不输出；拒绝链接则要求保留可操作信息。不是删除失败场景。
修改过程也曾暴露中文逗号连接的格式偏好识别失败，修复后连同条件和引用反例验证。
首次全套中间运行是 **20 失败 / 3501 通过（52.97 秒）**：其中 19 项来自新测试
夹具错误使用 SQLiteStore 上下文管理器，并非 19 个产品故障；另一项为旧首询措辞
断言，修正了兼容措辞但保留“只提真正未知上下文”的新行为。修复夹具后的材料优先
有效红测为 **5 失败 / 14 通过**，明确暴露生日或姓名抢占材料问题。
第二轮全套为 **9 失败 / 3517 通过（57.23 秒）**：7 项把新姓名回执中的短语
当作姓名追问，保留无追问断言并调整了回执措辞；2 项旧“下一份材料”断言预期
继续问个人信息，按新交互要求改为实际材料动作，同时保留一般清单的参考性质、
独立问题范围和无确认/交付断言。实际阅读还发现路线说明紧贴 URL 尾部，已分段并
补独立 URL 行断言；材料指导也统一使用当前链接偏好判断，避免误用第三方引用或
条件句，新增中英正反例。

## 来源与尚未解决的观察

2026-09-05 本地日期重新查看了 GOV.UK 的[申请页面](https://www.gov.uk/standard-visitor/apply-standard-visitor-visa)、
[官方路线检查](https://www.gov.uk/check-uk-visa)及[材料指南](https://www.gov.uk/government/publications/visitor-visa-guide-to-supporting-documents/guide-to-supporting-documents-visiting-the-uk)。
其中申请页面说明在线填表、可保存后继续和签证中心步骤；材料指南说明在申请地
合法居留证据及资金、职业等材料类别。这不是给产品新增实时联网检索。

本轮仍观察到：一些“日期仍未定，现在能做什么”的近义表达会落到个人信息问题；
学校不能出具特定证明时可能重复既有索取建议；“别一直问，告诉我怎么申请”在不同
合法但不理想的模型标签下表现不一致。这些观察不被本轮通过数关闭，后续需要独立
覆盖。更自由的自然表达、真实模型理解和不经指导的真人连续咨询仍需另外验证。
