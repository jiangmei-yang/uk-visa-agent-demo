# E-06 independent usability protocol — not a completed test

Purpose: assess the credential-free repository demo with a nontechnical participant who was
not involved in implementation. This does not validate real Gmail/WhatsApp operation or visa advice.
Use synthetic demo data only. Do not ask the participant to upload personal documents or keys.

## Before the session

- Record a pseudonymous participant ID, date, operating system, exact repository commit and
  whether Docker Desktop was already installed. Do not collect an unnecessary personal profile.
- Give the participant the repository link and `START_HERE.md`, not a live coaching session.
- Record whether internet/package downloads were available. Separate installation delays from
  application task time, but keep both in the evidence.
- With consent, record observations/screenshots excluding account details. Otherwise use notes.
- Do not pre-fill the score or silently restart/reset the app to hide a failure.

## Tasks, given without implementation hints

1. Start the demo from the downloaded repository and find where to try a case.
2. Work through the supplied fictional conversation. Explain why the first pack cannot be released.
3. Find the corrections requested, continue the case, and check whether confirmation is still needed.
4. Inspect the final summary, confirm only when it matches the scenario, and download/open the ZIP.
5. Explain what the ZIP contains, whether anything has been submitted to UKVI, and whether approval
   is guaranteed. Find the evidence supporting one corrected fact.
6. Stop and restart the demo. Explain whether existing data was retained and locate the case again.

Observe first; do not give menu names or commands unless asked. Any help is recorded verbatim.
If a task cannot be completed, retain the failure and proceed only when safe. Do not use a data
reset as an unrecorded recovery step.

## Acceptance declared before the run

- All six tasks completed without code edits, secret setup or database manipulation.
- Participant identifies both initial blockers and the need for confirmation before release.
- Participant opens the resulting archive and can locate a source/evidence explanation.
- Participant understands this is preparation for review, not a submitted or approved application.
- Restart preserves data. No accidental destructive action or cross-case disclosure occurs.
- No undisclosed assistance. Help from the written walkthrough is allowed; live coaching is a
  recorded usability issue, not an unassisted pass.

Record times and friction descriptively. Do not introduce an arbitrary perfect score or exclude
slow/failed participants after seeing their results. A single pass proves that observed session,
not universal ease of use.
